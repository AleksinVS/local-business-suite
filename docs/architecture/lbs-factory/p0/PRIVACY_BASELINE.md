## Подтверждение утверждений Factory 10 / ADR-0051

1. **Подтверждено:** файлы используют detect без mask и strict block; адаптер индексирует body безопаснее; свежий adapter_check read возвращает raw; title/object_id обходят body gate; chat sanitization секретов не является универсальной обработкой ПДн. Это риски кода, не доказательство произошедшей утечки.
2. **Подтверждено:** `workorders` и `waiting_list` выбирают pii_off в контракте (`contracts/ai/memory_sources.json:87`, `:130`) и адаптерах (`apps/workorders/source_adapter.py:70`, `apps/waiting_list/source_adapter.py:67`). WorkOrders рендерит description/comment (`:187`, `:200`); Waiting List рендерит свободный comment (`:175`). Из этих фактов не следует необходимость массово переключить профиль: требуется решение владельца источника/назначения.
3. **Уточнение:** прямой `read_search_document_text` уже требует свежего actor и object policy (`retrieval.py:273`); denied read не возвращает имена/пути. Нельзя описывать найденный privacy gap как отсутствие ACL вообще.
4. **Подтверждено:** `scope_tokens_match` — пересечение OR (`apps/memory/policies.py:256`), не будущее AND-наследование space + Note restrictions. Не менять текущую authority в P0.
5. **Подтверждено:** `_walk_knowledge_files` рекурсивно читает `*.md`, исключает только `index.md/log.md`, затем фильтрует status active (`knowledge_files.py:442`); весь CROW namespace не исключён. Некоторые будущие `status: stable` будут отфильтрованы, но markdown без status принимается как active — это не защитная изоляция raw/archive. Тот же обход идёт через `walk_all_knowledge_files` в graph (`:462`); legacy index пишет полное body и source ref (`:590`).
6. **Подтверждено:** writer пересоздаёт Frontmatter из фиксированного набора (`knowledge_files.py:84`, `:519`), не сохраняет unknown native CROW `id/sources/generated`. В нём status берётся из LBS active/superseded/deleted, type не выставляется. Reconcile регистрирует только уже известные active `MemoryKnowledgeItem` (`memory_reconcile.py:97`), не обнаруживает новые native Notes; при этом общий graph/index обход шире.
7. **Слова владельца:** production Windows + IIS существует и используется для Waiting List; перенос users/rights/departments/equipment/waiting_list входит в фактический контекст. Отсутствие production, заявленное ранее, отозвано. **Неизвестно:** развёрнута ли Wiki и есть ли source_data/автоиндексация/FTS/vector/Git-корпус на этом хосте. Даже если Wiki не используется, индексы могут содержать реальные доменные данные. **Локально:** authoritative flag=false установлен основным агентом, но его production значение неизвестно. Нельзя планировать сброс/перестроение как заведомо тестовое и нельзя заявлять, что миграции не нужны, до отдельной проверки хоста. Никакие production данные в этой работе не читались и не менялись.

## Обязательные проверки до P1 и реальных источников

- До **новой direct Wiki write** закончить PRIV-01/04: единый допуск `prepare_content` по source×destination до первого Git commit; отдельно external_llm. Это не требование внедрить тотальный PII detector. До подключения **реальных indexed source_data к AI** закончить PRIV-02/03 и чистое построение индекса из PRIV-05 (`10_CONTENT_PRIVACY_PIPELINE.md:168`).
- Добавить синтетические отрицательные end-to-end сценарии выбранного guarded/strict/off в реальных путях: body/title/object_id/path/citation/fallback; stale policy/source; detector failure; старый индекс; первый Git commit; адресат/аудитория ответа. Нейтральный текст должен оставаться полезным и искаться. Основа матрицы — PRIV-T01..T14 (`10_CONTENT_PRIVACY_PIPELINE.md:174`).
- Сохранить свежую авторизацию actor, source disabled/revocation, adapter_check и legacy pending. Сбой подготовки не допускает raw/metadata fallback, один заблокированный объект не останавливает остальные разрешённые объекты.
- До CROW: изоляция **всего** его namespace от legacy walker/writer/reconcile/index/log/graph; отдельный проектор; проверка OKF; единый writer и read barrier; compatible write partitions до merge; scoped metadata tree до classifier, проверка каждого raw/archive read, output/citations/audience. Реальные источники нельзя передать native XLSX split в обход подготовки sheet rows.
- До обработки реальных ПДн в новых Wiki/Git/raw/модельных маршрутах нужен отдельный принятый выбор хранения, retention/удаление/backup и назначения каждой модели. Реальные ПДн уже возможны в действующем Waiting List, особенно в свободном comment (`apps/waiting_list/source_adapter.py:175`); их наличие/отсутствие в индексах нельзя определить по отсутствию пользовательского Wiki workflow.
