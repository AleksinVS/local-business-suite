# Приемка: пользовательская карта группировки прав

## Результат

Пакет 12 принят после цикла основной архитектурный аудит → Luna-исполнитель →
тесты → независимая Luna-критика → Luna-исправление → финальное ревью.

Причина дефекта устранена: группировка больше не выводится из технического имени
права, его типа или широкого поля `section`. Для всех 20 текущих прав задано
явное сопоставление с пользовательской поверхностью. Все 11 действий с
заявками, карточками, исполнителями, статусами и колонками находятся в одной
группе «Канбан-доска».

Остальные группы соответствуют интерфейсу: «Медизделия», «Лист ожидания»,
«Аналитика», «Подразделения», «Доступ», «ИИ-центр» и «Память организации».
Неизвестное рабочее право не скрывается и попадает в «Прочие права», но тест
полноты требует явной классификации каждого нового контрактного права.

## Проверки

- `make verify-fast TEST_SCOPE=apps/settings_center/tests.py` — 74 passed,
  1 deselected, 9 subtests passed.
- `make verify-profile PROFILE=ui` после `make test-db-reset` — 269 passed,
  18 subtests; 17 Playwright smoke passed.
- Полный ожидаемый словарь 20 прав и порядок 11 прав канбана закреплены тестом.
- Неизвестное право проверено на сохранение в единственной резервной группе.
- Визуальная проверка Chromium 1440×1000 и 390×844 — успешно.
- `manage.py check`, `git diff --check`, проверка синтаксиса JS — успешно.

Первый запуск профиля остановился на ранее известном загрязнении повторно
используемой тестовой БД: отсутствовали тестовые доски `main` и `backlog`.
После штатного удаления только `.local` тестовой БД профиль прошел полностью.

## Границы

Контракт `role_rules`, значения прав, политики авторизации, подписанный
предпросмотр, применение и аудит не изменены. Новый ADR не нужен: исправлена
только пользовательская проекция принятой модели. Дополнительные условия входа
в ИИ-центр и очередь ревью памяти остаются отдельной задачей модели доступа.
