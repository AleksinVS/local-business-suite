# ADR-0039: Базовый просмотр канбан-доски без назначенной роли

- Статус: Superseded by ADR-0045
- Дата: 2026-08-11
- Связанные решения: ADR-0023, ADR-0034, ADR-0035, ADR-0038

## Контекст

Пользователь, созданный через SSO, LDAP или локальную форму, может не получить
контрактную роль сразу. Текущая политика в этом случае не возвращает ни одной
доступной доски и ни одной заявки. Назначать роль `customer` как значение по
умолчанию нельзя: кроме просмотра она разрешает создание заявки, изменение
собственных заявок, комментарии, вложения и отдельные переходы.

## Решение

1. Для активного авторизованного пользователя без единой контрактной роли
   применяется встроенный базовый профиль `default_board_viewer`.
2. Профиль разрешает только `view_scope=department_branch`. Все операции записи,
   переходы, комментарии, вложения и административные возможности запрещены.
3. Пользователь видит только доски, которые администратор уже открыл группе
   `customer`. Это не раскрывает закрытые или технические доски и не требует
   автоматического изменения их настроек.
4. После назначения любой явной контрактной роли встроенный профиль перестает
   применяться. Поэтому он не расширяет область назначенного техника, врача,
   менеджера или другой роли.
5. Итоговый доступ показывает базовый профиль и источник его возможностей, хотя
   он не является Django-группой и не редактируется как контрактная роль.
6. Кнопки записи скрываются в интерфейсе, но источником защиты остаются серверные
   политики и ответы 403/404.

## Рассмотренные альтернативы

### Автоматически назначать `customer`

Отклонено: роль содержит права записи и не соответствует принципу минимальных
полномочий.

### Создать и назначать постоянную группу `viewer`

Отклонено: потребовались бы миграция рабочих контрактов, массовое изменение
пользователей и правила совместимости с AD-синхронизацией. Ошибка синхронизации
могла бы оставить лишнюю группу рядом с более узкой ролью.

### Разрешить все доски каждому авторизованному пользователю

Отклонено: будущая закрытая доска стала бы доступна неявно.

## Последствия

- новый SSO-пользователь сразу открывает разрешенную канбан-доску;
- без реального подразделения карантинный пользователь видит структуру доски, но
  не получает заявки рабочих подразделений;
- назначение явной роли полностью заменяет базовый профиль;
- модель базы и рабочий контракт ролей не меняются;
- изменение требует тестов политики, селекторов, HTTP-записи и представления
  итогового доступа.

## Supersession 2026-08-26

ADR-0045 завершает действие неявного профиля: отсутствие контрактной роли теперь
означает отсутствие продуктового доступа. Вместо скрытого совместимого профиля
владелец может явно настроить контрактную роль, назначаемую только новым
пользователям, либо оставить безопасное значение «без роли».
