# Канбан: дерево подразделений в фильтре и сворачиваемый ИИ-чат

## Статус

Реализация и техническая приемка пакетов 01-04 выполнены 2026-08-06. Полный набор
прошел: 571 тест и 77 подтестов. Блок ожидает явную пользовательскую приемку;
архивный пакет 05 не запускался.

## Цель и пользовательская ценность

Упростить работу с заявками: оставить канбан единственным представлением, перенести
иерархию подразделений в постоянно доступный левый фильтр и сохранить ИИ-чат в той же
панели как быстро раскрываемый инструмент.

Результат должен сокращать переключения режима и не ухудшать права доступа, контекст ИИ,
работу с клавиатуры и мобильный сценарий.

## Исходное состояние

- `WorkOrderBoardView` выбирает `board|tree`, хранит выбор в Django session и формирует две
  проекции одного queryset.
- Старое дерево строится в `apps/workorders/tree.py`, рендерится через
  `templates/workorders/partials/tree_*.html` и управляется
  `static/src/js/workorder_tree.js`.
- Фильтр подразделений уже многозначный и включает ветви через `descendant_ids()`, но
  показан плоским выпадающим списком в верхней панели.
- HTMX меняет только `#workorders-view` и не приводит URL к фактическому состоянию формы.
- На странице канбана левую панель полностью занимает выбранный AI UI драйвер.
- `page_context.js` теряет все значения повторяемого фильтра, кроме последнего.

## Целевой пользовательский сценарий

1. Пользователь открывает канбан.
2. В левой панели видит доступное ему дерево подразделений. ИИ-чат свернут до компактной
   строки `Сообщение ИИ...` внизу.
3. Пользователь раскрывает ветви, при необходимости ищет подразделение по названию и
   отмечает одну или несколько ветвей.
4. Канбан обновляется без полной перезагрузки, URL получает канонические параметры, а
   остальные фильтры сохраняются.
5. Пользователь активирует строку ИИ. Дерево скрывается, чат занимает панель, фокус
   переходит в настоящее поле ввода.
6. Кнопка `Свернуть ИИ-чат` или `Escape` возвращает дерево. Текущий диалог и выполняющийся
   ответ сохраняются.
7. После перезагрузки фильтры восстанавливаются из URL, а чат снова свернут.

## Архитектурные границы

```text
visible_departments_queryset(user)
  -> нормализатор выбранных ветвей
  -> read model вложенного фильтра
  -> form-associated controls в левом sidebar
  -> канонический GET + HTMX push-url
  -> visible_workorders_queryset(user, board)
  -> канбан + безопасный PageContextEnvelope

локальный sidebar controller
  -> filters/chat (только память документа)
  -> native adapter | CopilotKit adapter
  -> существующий Django/AG-UI runtime без изменения протокола
```

Границы реализации:

- `apps.workorders` владеет выборкой заявок и board-specific read model фильтра;
- `apps.core.Department` остается общей доменной моделью, новая модель не нужна;
- общий контроллер панели владеет только представлением, фокусом и адаптивным слоем;
- AI-драйверы владеют своими полями ввода и жизненным циклом;
- браузерные идентификаторы подразделений не являются источником права доступа.

## Функциональные решения

### Фильтр подразделений

- множественный выбор сохраняется;
- выбор узла включает всю его ветку;
- выбранный предок делает выбранного потомка избыточным, URL нормализуется;
- невалидные и недоступные идентификаторы удаляются до применения;
- пустой выбор означает все доступные подразделения;
- отдельные состояния: `нет доступных подразделений` и `нет заявок по фильтрам`;
- локальный поиск не отправляет запрос на сервер и не изменяет отмеченные узлы;
- динамические счетчики заявок в узлах не входят в первый срез: они увеличивают стоимость
  запросов и могут создать побочный канал видимости.

### Состояния панели

| Состояние | Видимо | Фокус | Хранение |
|---|---|---|---|
| `filters` | дерево и компактный активатор ИИ | последний контрол фильтра или активатор | начальное при каждой загрузке |
| `chat` | проектный заголовок, драйвер и кнопка сворачивания | поле ввода драйвера | только память документа |
| весь sidebar свернут | существующая узкая панель | кнопка общего sidebar | существующий `sidebarCollapsed` |

Состояние потока ИИ не связано с визуальным состоянием панели. Завершение ответа не
открывает чат автоматически.

### Совместимость URL

- канонический маршрут не содержит `view`;
- полный GET с `view=tree|board` временно перенаправляется `302` на канонический URL без
  `view`; старый HTMX-запрос получает канбан и `HX-Replace-Url`;
- старый session key удаляется, `return_view=tree` не влияет на возврат после создания;
- повторяемые значения сохраняются как повторяемые параметры, а не CSV;
- HTMX-ответ не возвращает недоступные значения обратно в форму;
- смена доски сохраняет применимые фильтры.

## Область изменений

Предполагаемые изменения:

- `apps/workorders/views.py`, `selectors.py`, новый небольшой модуль проекции фильтра;
- `templates/workorders/board.html` и новые partial-шаблоны sidebar-фильтра;
- удаление partial-шаблонов, JS и Python-проекции старого дерева заявок;
- новый контроллер состояния левой панели и стили desktop/mobile;
- адаптер фокуса/статуса в `native_ai.js` и `static/src/copilotkit/main.jsx`;
- согласованная поддержка массивов фильтров в `page_context.js` и
  `apps/ai/page_context.py`;
- unit/integration/Playwright проверки и пользовательские руководства.

Изменение моделей, миграций БД, role rules, AG-UI wire contract и версий зависимостей не
планируется.

## Этапы

1. Нормализовать query contract и построить безопасную проекцию дерева подразделений.
2. Удалить режим дерева заявок и встроить filter-first shell в sidebar канбана.
3. Подключить общий lifecycle раскрытия к `native` и CopilotKit без размонтирования.
4. Исправить многозначные фильтры PageContextEnvelope с ограничениями санитайзера.
5. Выполнить unit, HTTP/HTMX, browser e2e и независимое security/UX ревью.
6. Обновить пользовательскую документацию и провести техническую приемку.
7. После явной приемки владельцем отдельным пакетом перенести план и workflow в архив.

Исполнительные границы и команды находятся в
`workflow/active/kanban-department-filter-ai-sidebar/`.

## Риски и меры

- **Потеря фильтров при HTMX.** Один GET-контракт и form-associated controls; HTTP-тест на
  полный набор повторяемых параметров.
- **IDOR через `department`.** Разрешение только через `visible_departments_queryset` до
  фильтрации; отдельная матрица ролей и подмены URL.
- **Рассинхронизация URL/UI/ИИ-контекста.** Один нормализованный набор значений и e2e после
  HTMX settle.
- **Потеря стрима при сворачивании.** Драйвер не размонтируется; состояние меняется CSS и
  атрибутами контейнера.
- **Зависимость от внутреннего DOM CopilotKit.** Проектный контроллер отправляет событие,
  а React-драйвер сам фокусирует свое поле; generic-код не ищет внутренние классы.
- **Мобильная панель перекрывает управление.** Отдельный off-canvas/sheet сценарий,
  focus trap, фон и размеры целей от 44 px.
- **Рост PageContext payload.** Ограничить число элементов массива, длину значения и
  общий размер; сервер повторно проверяет права.

## Проверки

Ступенчатая приемка:

```bash
git status --short
make check
make test-fast TEST_SCOPE=apps/workorders/tests.py
make test-fast TEST_SCOPE=apps/ai/tests
make test-integration TEST_SCOPE=apps/workorders/tests.py
node --check static/src/js/workorder_department_filter.js
node --check static/src/js/workorder_department_filter.js
node --check static/src/ai_ui/native_ai.js
npm run build:copilotkit
E2E_AI_UI_DRIVER=native npm run test:e2e -- --project=chromium --grep @workorders
E2E_AI_UI_DRIVER=copilotkit npm run test:e2e -- --project=chromium --grep "разворачивает и сворачивает"
make test
```

Полный `make test` выполняется один раз на финальной приемке. Длинные журналы и временные
артефакты пишутся только в `.local/`.

## Definition of Ready

- цель, non-goals и UX-состояния зафиксированы;
- ADR-0037 принят;
- write scope разделен на пять task packet, включая отдельное архивирование после
  приемки владельцем;
- определены unit, integration, e2e и security проверки;
- версии AG-UI локально согласованы и не требуют обновления в этом срезе.

## Definition of Done

- старый режим дерева и его мертвые файлы удалены без ослабления branch access;
- фильтр дерева работает по URL и HTMX для всех разрешенных ролей;
- `native` и CopilotKit проходят общий lifecycle раскрытия/сворачивания;
- page context не теряет многозначные фильтры и проходит серверную валидацию;
- desktop/mobile и клавиатурный сценарии покрыты e2e;
- выполнены `make check`, целевые тесты, интеграционные сценарии и один `make test`;
- обновлены ADR, guides, `.desc.json`, `PROJECT_STRUCTURE.yaml`, backlog;
- workflow содержит отчеты исполнителей, независимую приемку и ретроспективу, затем
  переносится в `workflow/archive/2026/`.

## Не входит в работу

- счетчики заявок у подразделений;
- серверное сохранение раскрытых ветвей или состояния чата;
- изменение ролей и областей доступа;
- новая модель организации;
- обновление AG-UI/CopilotKit;
- изменение полной страницы ИИ-чата;
- новая логика создания заявки из узла фильтра.
