# Приёмка задачи 05 — режим перемещения из списка остатков

Статус: принято основным агентом после исправлений независимого Sol-high review.

## Принятый результат

- Перемещение выполняется из фильтруемого постраничного списка положительных доступных остатков.
- Несколько выбранных строк образуют один атомарно проводимый документ перемещения.
- Назначение ограничено тем же подразделением, активным складом и доступным адресом.
- Ключ идемпотентности входит в подписанную команду; повтор принимается только при полном совпадении пользователя, даты, строк, количества, склада и адреса.
- Враждебные и выходящие за разрядность значения количества отклоняются до сериализации.
- Конкурирующие операции используют единый порядок блокировок с обычным проведением.
- Рабочие URL, навигация и адрес приёмки по умолчанию подключены к порталу.

## Проверки

- Независимое Sol-high review: первоначальные замечания исправлены; последний выявленный случай несогласованной пары склада и адреса закрыт ранней доменной проверкой и сравнением склада при повторе.
- Финальный локальный прогон основного агента:
  `pytest apps/warehouse/tests/test_relocation_mode.py -q -p no:cacheprovider --ds=config.settings`
  — `14 passed, 4 skipped`.
- Четыре пропуска относятся только к PostgreSQL-сценариям реальных блокировок: перерасход, противоположный порядок позиций, конкуренция с обычным проведением и одновременный повтор ключа.

## Остаточный риск

Перед производственным выпуском требуется выполнить определённую в тестах конкурентную матрицу на PostgreSQL и браузерный сквозной сценарий. На SQLite семантика `SELECT FOR UPDATE` достоверно не проверяется.
