# ADR-0036: Изоляция автоматических ресурсов браузера от Windows SSO

- Статус: Accepted
- Дата: 2026-08-06

## Контекст

Под IIS/wfastcgi первый запрос страницы и автоматический `/favicon.ico` могут
уйти параллельно без Django-сессии. Из-за искажённого `PATH_INFO` favicon
превращался в `/`, попадал на главную и выполнял второй вход через
`PersistentRemoteUserMiddleware`. Каждый вход вызывал `login()` и ротацию CSRF;
последний `Set-Cookie` мог не соответствовать токену уже отрисованной формы.

Похожий побочный эффект возможен у корневого PWA service worker, стандартных
browser icons и отсутствующей статики: публичный ресурс не должен создавать
пользователя или SSO-сессию.

## Решение

1. Канонический `web.config` исключает `favicon.ico` из FastCGI отдельным IIS
   `location`; IIS отдаёт 404 без Django и Windows SSO.
2. `ManualAuthAwareRemoteUserMiddleware` не запускает Remote User SSO для
   автоматических публичных ресурсов: favicon, apple-touch icons,
   `browserconfig.xml`, `/service-worker.js` и `/static/`.
3. IIS-совместимый `PATH_INFO` middleware не превращает неизвестные browser icons
   в главную, но восстанавливает `/service-worker.js`, чтобы публичный корневой
   маршрут продолжал работать.
4. Шаблон явно объявляет favicon и apple-touch-icon из `/static/`.
5. Windows deployment-скрипты проверяют наличие favicon bypass в `web.config` и
   выводят операционное предупреждение для старых конфигураций.
6. Существующий хост обновляется идемпотентным скриптом с резервной копией,
   атомарной записью, IIS validation, точечным recycle и автоматическим откатом.

## Рассмотренные альтернативы

### Сбрасывать флаг записи CSRF-cookie после SSO

Отклонено: другой параллельный запрос всё равно может отрисовать `base.html`,
вызвать `get_token()` и записать собственный секрет.

### Оставить только исправление в Django

Отклонено как единственная мера: автоматический favicon вообще не относится к
приложению и должен завершаться до FastCGI. Django-проверка сохраняется как
защита старых или ошибочных host-specific конфигураций.

### Отключить ротацию CSRF при входе

Отклонено: ротация при аутентификации — штатная защита Django. Нужно убрать
побочный вход служебного запроса, а не ослаблять механизм безопасности.

## Последствия

- новые и обновлённые IIS-хосты должны перенести `location` в приватный
  `web.config.template`;
- старый IIS-конфиг перестаёт создавать конкурирующую SSO-сессию благодаря
  резервной проверке приложения, но всё равно считается неполным;
- root service worker остаётся публичным и не создаёт учётных записей;
- реальная проверка IIS handler mapping остаётся операционной проверкой на
  Windows-хосте, поскольку Linux-набор тестов не исполняет IIS/wfastcgi.
- повторный запуск updater не создаёт дубликаты; host-specific backup остаётся
  рядом с `web.config` и не попадает в Git.
