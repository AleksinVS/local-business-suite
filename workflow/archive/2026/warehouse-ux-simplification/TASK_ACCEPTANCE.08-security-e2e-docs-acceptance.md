# Приёмка задачи 08 — безопасность, сквозные сценарии и документация

Статус: технически принято основным агентом 2026-09-04.

## Принятый результат

- Независимое ревью проверило складские области просмотра и операций,
  назначения в памяти, FileHub, архивные справочники и запрещённые места
  хранения; замечания исправлены.
- Просмотр остатков отделён от права перемещения: пользователь может видеть
  разрешённый остаток, но элементы управления перемещением получает только для
  подразделений с операционным правом.
- Обычные документы принимают только активные места хранения назначения
  `AVAILABLE`; карантин и техническое нераспределённое место отклоняются.
- Исключение для нераспределённого начального остатка ограничено legacy-импортом,
  суперпользователем и внешним идентификатором `legacy:*`.
- Архивные значения сохраняются в уже существующих документах, но не выдаются
  как новые подсказки.
- Матрица значимых полей закрыта без статусов `planned` и `audit`.
- Руководства, архитектура, развёртывание, планирование и карта проекта
  актуализированы. Организационная процедура переключения со старой системы не
  фиксировалась по решению владельца.

## Итоговые проверки

- полный набор `apps/warehouse`: успешно; четыре PostgreSQL-only проверки
  конкуренции пропущены в локальном SQLite-профиле;
- `warehouse_acceptance_e2e`: успешно на чистой мигрированной базе;
- `manage.py check`: успешно с известным предупреждением
  `settings_center.W002`;
- `makemigrations --check --dry-run`: изменений схемы вне миграций нет;
- `validate_architecture_contracts`: контракты корректны; локальная среда
  сообщает ожидаемые предупреждения об отсутствии production runtime-копий;
- 12 автономных Playwright-сценариев общего автодополнения, правой панели и
  табличного редактора: успешно;
- целевая регрессионная матрица всех изменённых модулей: успешно;
- `collectstatic`, `check_staticfiles`, `compileall`, `node --check` и
  `git diff --check`: успешно.

## Остаточные риски

- PostgreSQL-конкурентные тесты должны выполняться в CI или deployment-профиле.
- Авторизованный Playwright-сценарий всего портала требует тестовой учётной
  записи; автономные браузерные контракты этого блока выполнены локально.
- Общий набор проекта не зелёный по причинам вне этого этапа: LanceDB аварийно
  завершается на данном процессоре, runtime-копии контрактов других направлений
  отстают от defaults, а часть security-тестов требует Windows symlink privilege.
