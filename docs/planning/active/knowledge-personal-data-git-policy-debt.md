# Архитектурный долг: персональные данные в LBS Wiki, CROW raw и Git

**Статус:** Open / требует отдельного решения.
**Дата постановки:** 2026-10-21.
**Приоритет:** до первого пилота на реальных источниках с персональными данными; не блокирует архитектуру и синтетический пилот CROW/OKF.
**Владелец решения:** владелец архитектуры LBS совместно с владельцем данных и ответственным за безопасность/правовые основания обработки.
**Связи:** [LBS Factory v3.4](../../architecture/lbs-factory/00_README.md), [Content Privacy Pipeline](../../architecture/lbs-factory/10_CONTENT_PRIVACY_PIPELINE.md), [CROW/OKF](../../architecture/lbs-factory/11_CROW_OKF_INTEGRATION.md), [ADR-0051](../../adr/ADR-0051-crow-pluggable-okf-knowledge-provider.md), [предварительный ADR-0012](../../adr/ADR-0012-data-anonymization-and-privacy-pipeline.md).

## Что принято, а что ещё нет

**Принята архитектура**: LBS Access решает доступ к пространству/заметке/источнику, CROW управляет материалами OKF, исходный CROW `raw` сохраняется на первом этапе, общие правила назначения обработки и запрет неразрешённой передачи наружу сохраняются. Запись секретов/учётных данных в доступные знания запрещена. Право читать данные внутри LBS не означает права передавать их облачной модели.

**Не принято**: обязательное обнаружение персональных данных в любом источнике; обязательное извлечение/маскирование/псевдонимизация; единый режим `pii_guarded` по умолчанию; необходимость отдельного NER/DLP-сервиса; конкретный порядок обращения с персональными данными в заметках, `raw`, Git и backup.

Согласование LBS Factory и ADR-0051 **не закрывает этот долг** и не объявляет содержимое с персональными данными автоматически разрешённым для Git или CROW.

## Почему решение необходимо

Файлы `raw/` CROW — подготовленные исходные тексты; они могут содержать персональные или иные ограниченные сведения даже после нормализации. OKF-заметки, `index.md`, `log.md`, ссылки, описания, история `.archive/`, поисковые проекции, следы модели и Git commits могут сохранять или повторно раскрывать такие сведения. Git и резервные копии затрудняют выборочное удаление, особенно при распространении клона репозитория.

При этом безусловное обезличивание корпоративных текстов способно уничтожить необходимые сведения и не гарантирует фактическую анонимность. Обязательность маскирования нельзя выводить только из наличия детектора.

## Что решить отдельным ADR / политикой

1. **Классы источников и цели:** какие реальные источники содержат ПДн, какие цели обработки допустимы, кто определяет правовое основание и разрешённую аудиторию.
2. **Матрица размещения:** можно ли хранить ПДн в: (а) оригинале системы-владельца, (б) CROW `raw/`, (в) `.archive/`, (г) **каноническом Markdown/Git Wiki** (включая Frontmatter, `index.md`, `log.md`), (д) FTS/vector/кеше, (е) логах/trace и backup. Отдельно для обычных, чувствительных и высокорисковых наборов.
3. **Режим обработки:** сохранять исходное содержимое, не загружать его, использовать выборочное маскирование, устойчивую псевдонимизацию или строгий отказ — **по типу источника и назначению**, а не универсально.
4. **Модели и маршруты:** различить локальную модель, внешнюю LLM, поиск в закрытом контуре и экспорт. Не разрешать внешний egress по факту локальной авторизации.
5. **Право на забвение и жизненный цикл:** сроки, отзыв исходных прав, изменение целей, удаление/исправление канонической заметки, raw, архива, производных индексов, Git history/clones и backup; критерий достижимой очистки.
6. **Привязка производных знаний:** когда обезличенная/обобщённая заметка может иметь права шире исходного документа, как подтвердить достаточность обработки, кто утверждает расширение аудитории.
7. **Минимальные тесты:** синтетические ПДн, сценарии с запретом публикации в Git и cloud, внутренним разрешённым чтением, отзывом прав, удалением связанных данных, точностью поиска без чрезмерного маскирования.

## Варианты для сравнения, но не принятые решения

- **Минимальный:** разрешённые закрытые источники хранятся в управляемом `raw`, а каноническая Wiki/Git содержит только безопасно публикуемые производные знания; не вводить универсальный детектор.
- **Настраиваемый:** профили `pii_off / pii_guarded / pii_strict` и допустимость `raw`/Git/LLM задаются типом источника и целью, с проверяемыми преобразованиями.
- **Более строгий:** источники с определёнными классами персональных данных обрабатываются локально или не включаются в Wiki; редактирование/маскирование для узкого класса обязательно.
- **Усиленный:** добавление NER/DLP только при измеренной недостаточности базовых правил и установленной бизнес-потребности.

## Временные ограничения до закрытия долга

- Синтетический или обезличенный **по выбранным для стенда правилам** набор данных допустим для пилота CROW/OKF.
- Не включать произвольные реальные ПДн в Git-канон/историю, общую Wiki или внешний LLM **без отдельной согласованной политики конкретного источника и назначения**.
- Существующие LBS Access, разграничение пространств/заметок/источников, Credentials/secret gate, аудит и запрет неразрешённого внешнего egress обязательны.
- Нет обязательного массового маскирования данных, обязательного обнаружения каждого PII или отдельного NER/DLP; это предмет данного долга.
- Этот долг **не блокирует** реализацию кэша CROW, `Steps.select`, `Researcher.ask`, OKF v0.2 и тестов на синтетических данных.

## Критерии закрытия

- Принят отдельный ADR (либо явно ограниченное дополнение к ADR-0012) с матрицей **тип источника × хранилище × назначение** и решением по **ПДн в Git**.
- Есть назначенный владелец разрешений на хранение/передачу данных, разумные сроки хранения/удаления и сценарии восстановления.
- В документации CROW и privacy устранены противоречия; созданы соответствующие тесты для выбранного режима.
- Обозначено, какие реальные источники допустимо подключить первыми и какие остаются запрещёнными/условными.
- После утверждения решение снимается из `docs/planning/backlog.md`, а этот план переносится в `docs/planning/archive/` по правилам AGENTS.md.

**Следующее действие:** отдельное обсуждение варианта хранения реальных ПДн в защищённом CROW `raw` и в Git-заметках, с явными примерами классов документов и каналов LLM. Не считать отсутствие принятого решения согласием на публикацию ПДн в Git.
