# Импорт и очистка данных листа ожидания

Команды предназначены для администратора приложения и работают через модели
Django. Перед операциями с рабочими данными сделайте резервную копию базы.

## Интерфейс администратора

Активный суперпользователь может открыть:

```text
Настройки → Данные листа ожидания
```

Прямой адрес: `/settings/waiting-list-data/`.

На странице показано текущее количество записей и событий журнала. Форма
импорта позволяет сначала проверить файл без записи, затем загрузить его. Автором
операции становится текущий суперпользователь. Форма очистки требует вручную
ввести `DELETE_WAITING_LIST`. Обычным пользователям и сотрудникам без статуса
суперпользователя страница недоступна.

## Проверка файла перед импортом

```bash
.venv/bin/python manage.py import_waiting_list "drafts/Выгрузка.txt" \
  --author <логин> \
  --dry-run
```

Файл должен быть в UTF-8 или UTF-8 с BOM, иметь разделитель-табуляцию и колонки:

```text
Услуга  ФИО  Дата рождения  Телефон  Дата записи  История изменений
Дата бирки  Дата окончания  Cito  Статус  Комментарий  Период
```

Многострочное поле `История изменений` поддерживается. Весь файл проверяется до
начала записи; при ошибке ни одна строка не импортируется.

## Импорт

```bash
.venv/bin/python manage.py import_waiting_list "drafts/Выгрузка.txt" \
  --author <логин>
```

`--author` — логин активного пользователя, который будет записан техническим
автором импортированных записей и событий журнала. Исходные ФИО сотрудников из
колонки истории сохраняются в тексте события.

Соответствие полей:

- `Дата бирки` → целевая дата;
- `Дата окончания` → крайняя дата;
- `Период` → дата и время создания записи;
- `История изменений` → журнал изменений;
- `Дата записи` не имеет отдельного поля в текущей модели и сохраняется строкой
  `Дата записи (импорт): ...` в комментарии;
- время из `Даты бирки` и `Даты окончания` отбрасывается, поскольку целевые поля
  модели хранят календарную дату.

По умолчанию команда откажется загружать данные в непустой лист, защищая от
случайных дублей. Для осознанного добавления используйте `--append`:

```bash
.venv/bin/python manage.py import_waiting_list "data/import/Выгрузка.txt" \
  --author <логин> \
  --append
```

Чтобы после импорта сразу обновить производные данные поиска и аналитики,
добавьте `--reconcile-projections`. Без флага их обновит штатный периодический
запуск `source_adapter_reconcile`.

## Очистка

Сначала посмотрите объём удаления:

```bash
.venv/bin/python manage.py clear_waiting_list --dry-run
```

Для фактического удаления всех записей и их журнала нужна точная подтверждающая
фраза:

```bash
.venv/bin/python manage.py clear_waiting_list \
  --confirm DELETE_WAITING_LIST
```

После удаления команда запускает штатную сверку источника `waiting_list`, чтобы
деактивировать поисковые и аналитические проекции удалённых записей. Параметр
`--skip-projections` нужен только для аварийного режима, когда контуры памяти или
аналитики временно недоступны; после этого сверку необходимо запустить вручную:

```bash
.venv/bin/python manage.py source_adapter_reconcile \
  --source-code waiting_list \
  --target all \
  --backend all
```
