# Приемка документационного среза

## Статус

Accepted for implementation planning.

Это приемка полноты проектной и исполнительной документации, а не приемка реализации.

## Проверено

- пользовательское требование разложено на однозначные состояния `filters/chat`;
- решение полностью удаляет отдельный tree-mode, а не сохраняет его скрытой веткой;
- дерево ограничено подразделениями и серверными правами;
- URL, HTMX, reload и старые ссылки имеют определенный контракт;
- native и CopilotKit разделяют UI lifecycle без изменения AG-UI runtime;
- сохранены CSRF, signed actor, allow-list UI-команд и server-side resolution;
- описаны mobile, keyboard, focus и reduced-motion требования;
- task packets имеют непересекающиеся по этапам цели, явный write scope и команды;
- структурные описания входят в write scope пакета 01, а архивирование вынесено в пакет
  05 и заблокировано до явной приемки владельцем;
- финальная приемка требует unit, integration, e2e, security review и `make test`;
- миграция БД и обновление зависимостей обоснованно не требуются.

## Замечания, учтенные до приемки

- зафиксирован перенос общего обработчика `workordersChanged` до удаления старого JS;
- raw `department` нельзя разрешать через общий `Department.objects`;
- поиск по подразделениям также должен учитывать доступный queryset;
- старый session key и `return_view=tree` включены в compatibility matrix;
- многозначные фильтры PageContextEnvelope выделены в security-sensitive scope.

## Условие начала реализации

Исполнитель начинает с пакета 01 и перед каждой серией проверок фиксирует
`git status --short`. Чужие незакоммиченные изменения не изменяются и не откатываются.
