# Отчёт 03: интеграция, тесты и документация

## Результат

Объединены серверный контур назначения ролей и карточный редактор. При итоговом
просмотре закрыты три дефекта: служебные поля роли исключены из расчёта риска,
редактируемые описания прав исключены из audit-маркеров, общий JSON-редактор
контракта перенаправлен в защищённый карточный редактор. Добавлена навигация для
пользователя с `manage_roles` без требования `is_staff`.

Чтобы не потерять прежнее локальное управление пользователями, редактирование
профиля и технических флагов сохранено отдельным маршрутом суперпользователя.
Этот маршрут не изменяет роли и технические группы.

Постороннее незавершённое изменение `User.department` возвращено к исходной
семантике `SET_NULL`, `null=True`; миграции снова согласованы с моделью.

## Проверки

- `make check` — успешно после локального `collectstatic`; оставшиеся legacy-файлы
  в игнорируемом `staticfiles/` не блокируют проверку.
- затронутый набор — `201 passed, 2 subtests passed`;
- `make contracts` — успешно, runtime `role_rules` совпадает с дефолтом;
- `makemigrations --check --dry-run` — `No changes detected`;
- `access_management_e2e` — успешно после применения миграции `accounts.0007`,
  тестовые данные откатились;
- `git diff --check` — успешно;
- полный `make test` — `541 passed, 65 subtests passed, 2 failed`.

Два падения полного набора относятся к существующим тестам версий статических
ресурсов ИИ-чата: ожидаются фиксированные строки версий `native_ai` и
`copilotkit`, тогда как шаблон выдаёт хеш содержимого. Контур прав эти файлы не
изменяет. Версии AG-UI/CopilotKit не обновлялись.

## Независимая проверка

Проверочный субагент подтвердил авторизацию/IDOR, сохранение технических групп,
подписанный preview, конкурентную защиту, итоговые источники, XSS-защиту,
уникальный подсчёт сотрудников и отсутствие N+1. Найденное копирование
редактируемого описания в audit исправлено и закрыто регрессионным тестом.

## Документация

Обновлены README, ADR-0034, POLICY_MODEL, пользовательское руководство,
planning/workflow и описания структуры. Новая модель безопасности или новый
runtime-сервис не вводились, поэтому отдельный ADR не потребовался.
