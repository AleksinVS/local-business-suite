# Архитектура проектной вики с агентом и CROW

Основной агент ведёт тематические статьи в Markdown. Навык задаёт ему правила работы со знаниями. CROW помогает искать статьи, классифицировать изменения, обрабатывать исходные документы, выявлять противоречия и поддерживать структуру вики. Для функций, которые CROW уже предоставляет в удобном для агента виде, достаточно штатного вызова. Формат статей — Open Knowledge Format (OKF) v0.2.

**Редакция концепции: 20 ноября 2026 года.** Возможности сверены с [CROW 1.0.5](https://github.com/crow-hq/llm-wiki-v2/tree/v1.0.5). Установленную версию и подключённые операции каждый проект фиксирует отдельно. Переход с 1.0.1 не меняет распределение ролей ниже и не требует миграции формата статей.

## Роли и границы

| Компонент | За что отвечает |
| --- | --- |
| Основной агент | Понимает контекст работы, читает статьи и первоисточники, решает, что изменилось в знаниях. Готовит и проверяет законченный набор правок, включая связанные статьи, ссылки и индекс затронутого раздела. Одно расследование может уточнить несколько статей. |
| Навык работы с вики | Определяет, когда искать знания, что заслуживает записи и как проверять статьи. В проекте к нему добавляют путь к вики, доступные инструменты и способ сослаться на источник. |
| CROW | Ищет статьи, принимает исходные документы, предоставляет классификатор, указывает на возможные расхождения, предлагает и выполняет переносы. Работает с тем же набором статей, который редактирует агент. |
| Адаптер, если нужен | Делает конкретную возможность доступной агенту. Например, превращает типизированный запрос к Python-классификатору в одну операцию агента. Его можно заменить, сохранив файлы вики и правила навыка. |

Для запуска достаточно одного агента с навыком, файлового редактора и штатной поставки CROW. Отдельный сервис публикации в этой схеме не требуется. Если модель классификации недоступна, агент продолжает работу через поиск BM25, чтение и прямую редактуру.

## Способ подключения CROW

| Условия проекта | Подключение |
| --- | --- |
| Агенту доступен весь выбранный корпус; достаточно штатных операций | Штатный MCP CROW над каталогом вики. Клиент может запускать его через stdio. Агент читает найденные страницы и редактирует Markdown обычным редактором проекта. |
| Нужна отдельная классификация правки или проект ограничивает набор доступных статей, источники либо порядок записи | Тонкий адаптер к нужным Python-компонентам CROW. Он принимает только допущенные проектом данные и возвращает результат конкретной операции. Штатные операции, для которых адаптация не нужна, остаются доступными напрямую в разрешённой области. |

Оба варианта используют один формат статей и одни правила авторства. Наличие MCP-инструмента `remember` не меняет выбор пути: подготовленный агентом набор статей сохраняется напрямую; штатная обработка CROW применяется к исходному материалу, который ещё нужно разобрать. Это правило закрепляется в навыке проекта рядом с описанием доступных инструментов.

В 1.0.3–1.0.4 исправлен первый запуск MCP без сохранённых настроек и создание пустой вики. При отсутствии настроек CROW передаёт модельные запросы клиенту; существующая конфигурация сохраняет свой приоритет. Режимы `client` и `hybrid` существовали уже в 1.0.1. В `hybrid` модель клиента пишет, а настроенный классификатор принимает решения, но маршрутизацией, слиянием и записью по-прежнему управляет CROW. Этот режим можно использовать для штатной обработки исходников независимо от прямой авторской редактуры. [Запуск MCP](https://github.com/crow-hq/llm-wiki-v2/releases/tag/v1.0.3) · [Пустая вики](https://github.com/crow-hq/llm-wiki-v2/releases/tag/v1.0.4) · [Модели клиента](https://github.com/crow-hq/llm-wiki-v2/blob/v1.0.5/docs/wiki/memory.md#which-models-do-the-work)

Если проект ограничивает доступ, он проверяет права до передачи текста CROW или модели. Параметр `where` фильтрует заметки по полям и не является проверкой прав. Аннотация MCP `openWorldHint: false` описывает область действия инструментов; она не обеспечивает разграничение доступа или локальное выполнение модели. [Ограничения MCP](https://github.com/crow-hq/llm-wiki-v2/blob/v1.0.5/docs/wiki/memory.md#more-than-one-wiki) · [Аннотации 1.0.5](https://github.com/crow-hq/llm-wiki-v2/releases/tag/v1.0.5)

## Два пути в одну вики

**Агент уже исследовал вопрос.** Он ищет существующие объяснения, открывает полные тексты и при необходимости переходит по ссылкам за пределы поисковой выдачи. Затем правит нужные файлы обычным редактором проекта. Уточнение существующей темы попадает в соответствующий раздел. Самостоятельный вопрос может получить новую статью. Если сведения уже описаны, агент завершает задачу без записи. Отправлять готовую статью в `remember` или `ingest` означало бы поручить CROW повторный синтез и выбор места для уже адресованной правки.

**Поступил исходный документ.** Например, вышла новая редакция инструкции, которую агент ещё не разбирал. Документ передают в штатный `Wiki.ingest`. Для повторного импорта полезно передать устойчивый идентификатор и версию источника через `Origin`. CROW сохраняет подготовленный исходник, выбирает тему и создаёт либо дополняет заметку. При обычном импорте текста CROW формирует одного основного кандидата. Если документ меняет несколько самостоятельных тем, агент может дочитать оригинал и уточнить остальные статьи напрямую. При настройке синхронизации входную папку с документами держат отдельно от выходной вики.

## Правила для навыка автора

Этот раздел можно перенести в инструкции агента. Достаточно указать местоположение вики и принятый в проекте способ сохранения.

1. Перед существенной работой найди прежние решения по теме. Открой подходящие статьи и проверь, для какой версии или ситуации они написаны.
2. Пока у тебя есть контекст задачи, сформулируй вопрос следующего читателя. Что он сможет понять, проверить или сделать благодаря новому знанию? Статус выполнения и ход сеанса оставь в задаче. Частный, воспроизводимый вывод стоит сохранить с явным условием применимости.
3. Найди все темы, ответ в которых изменился. Используй поиск, ссылки и при необходимости классификатор. Можно выбрать статью за пределами предложенного списка. Перед заменой целого раздела дочитай его и сохрани прежние выводы, которые по-прежнему верны.
4. Запиши вывод своими словами и приложи проверяемое основание — версию инструкции, тест, измерение или конкретный фрагмент источника. Обозначь, где вывод проверен и что остаётся гипотезой. Добавляй ссылку на соседнюю статью, когда она помогает применить вывод.
5. Перечитай результат глазами участника, который не видел задачу. Проверь весь набор своих правок, основания и переходы. При пересечении с чужой правкой перечитай текущий текст и согласуй смысл. Если правки нельзя совместить, сообщи о конфликте и сохрани обе версии. Чужие незавершённые изменения оставь их владельцу. Если повторное наблюдение ничего не добавило, оставь вики без изменений.

**Пример.** Сообщение «повторно загрузили файл, проверка прошла» остаётся в журнале задачи. Если тест установил, что повтор безопасен только при сохранении внешнего идентификатора, а инструкция предлагает создать новый, меняются две статьи. В «Повторной загрузке» агент добавляет условие и ссылку на тест. В «Идентификаторах» исправляет правило для повторной отправки. Следующий участник найдёт ответ независимо от того, с какой темы начнёт поиск.

## Инструменты CROW и основания для адаптера

| Задача | Штатная возможность CROW 1.0.5 | Что делает агент или адаптер |
| --- | --- | --- |
| Найти и прочитать | `Wiki.search` или MCP-инструмент `search` находит кандидатов по содержанию. MCP-инструмент `read_note(path)` возвращает полный текст. Для обычного поиска BM25 модель не нужна. | Агент может сразу пользоваться MCP или читать найденный Markdown с диска. |
| Классифицировать предлагаемую правку | Python-класс `llmw2.Classifier` предоставляет отдельные вызовы `choice`, `nouls` и `ask`. Готовой MCP-команды для классификации произвольной правки в этой версии нет. | Если нужна отдельная операция, адаптер передаёт формулировку вывода и фрагменты найденных статей. Например, предлагает для каждой статьи варианты «уже описано», «дополняет», «возможное противоречие» и «данных недостаточно». Возвращает подсказку без записи. При неоднозначном результате агент дочитывает источники. |
| Обработать исходный материал | `Wiki.ingest` принимает документ и его происхождение. MCP-инструмент `remember(text, title?)` запускает штатную обработку текста. | Источник можно передать напрямую. Адаптер полезен, если проекту нужно получить конкретную версию из внешней системы или подготовить документ в читаемом виде. |
| Найти и устранить противоречие | При подготовке ответа по нескольким заметкам штатная проверка `ask/conflict` может указать расходящиеся утверждения. Для новой версии одного источника предусмотрено обновление при выполнении условий CROW. | Для явной проверки двух фрагментов можно вызвать классификатор через тот же адаптер. Агент сравнивает версии, даты действия и область применения. Если обе нормы верны в разных условиях, уточняет обе статьи. Если источник подтверждает замену, исправляет действующую норму. Когда оснований мало, сохраняет обе позиции и открытый вопрос. |
| Перестроить вики | `Wiki.audit_routes(apply=False)` с настроенным классификатором предлагает переносы. `move_note` перемещает заметку в существующий раздел и обновляет ссылки. | Для переноса агент вызывает штатную команду. Для смыслового разделения или объединения он сам редактирует тексты, распределяет основания и проверяет входящие ссылки. |

## Описания инструментов для агента

Описание каждой доступной операции указывает, что она делает, когда нужна, что возвращает, какие данные изменяет и при каких условиях отказывает. Это часть интерфейса агента: навык задаёт общий порядок работы, а описание помогает выбрать действие в конкретный момент. Такой подход принят в [MCP CROW 1.0.5](https://github.com/crow-hq/llm-wiki-v2/releases/tag/v1.0.5).

| Операция | Что должно быть понятно из описания |
| --- | --- |
| Поиск | Возвращает кандидатов в разрешённой области. Для правки агент затем открывает полную статью и проверяет основания. |
| Чтение | Возвращает текст; сведения о версии, нужные для последующей записи, агент получает средствами проекта. Переход по ссылке требует такой же проверки доступности, как поиск. |
| Классификация или сравнение | Возвращает отношение между утверждениями и доступную оценку модели. Ничего не записывает. Неуверенность или недоступность модели позволяют продолжить чтение и редактуру без подсказки. |
| Прямая редактура | Сохраняет подготовленные агентом статьи выбранным в проекте способом. Описание объясняет проверку исходной версии, последствия удаления, фиксацию изменений и поведение при конфликте или повторе операции. |
| Импорт или перестройка | Явно обозначает, что запускает модельную обработку либо меняет файлы и ссылки. `rebuild` восстанавливает из исходников и не служит способом сохранить авторскую правку. |

Конкретные имена и параметры берутся из доступных средств проекта. Эта таблица не требует отдельного сервиса записи или нового набора команд, если штатные инструменты уже выполняют нужную работу.

## Статус статьи и доверие к содержанию

В OKF v0.2 верхнеуровневое поле `status` необязательно. Для обычной действующей статьи его можно пропустить, что означает `stable`. Значение `draft` обозначает черновик, `deprecated` сохраняет прежнюю статью для истории и ссылок. Если приложение называет действующую статью `active`, это его внутреннее обозначение. Записывать `status: active` в OKF не нужно.

Доверие отражает отдельное поле `verified` с указанием, кто и когда проверил содержание. Статья без него может быть `stable` и доступна для чтения. После смысловой правки проверьте, к какой редакции относится прежнее подтверждение. CROW 1.0.5 сохраняет незнакомые поля при обычном обновлении, а его дерево и штатный поиск сами не исключают страницы по верхнеуровневому `status`. Если поиск проекта должен предлагать только действующие статьи, это условие применяет вызывающая сторона. [OKF, доверие и жизненный цикл](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/0b87c52c6ef999286c745e19998fdfcd03d5dbee/SPEC.md#L366-L422) · [Совместимость CROW с OKF](https://github.com/crow-hq/llm-wiki-v2/blob/v1.0.5/README.md#L444-L446)

## Обновления и заменяемость

Точка интеграции — открытый пакет `llmwiki2` с Python API или его штатным MCP. Настольное приложение может быть отдельным клиентом, но не является обязательной частью концепции. Проект закрепляет проверенную версию поставки и обновляет её вместе с проверкой реально используемых операций. Публичные документированные интерфейсы имеют гарантии совместимости с 1.0.0; внутренние классы в эти гарантии не входят. [Границы совместимости](https://github.com/crow-hq/llm-wiki-v2/blob/v1.0.5/docs/library/index.md#compatibility)

В частности, `Wiki.search` работает с вики, а отдельного публичного поиска по переданному списку допущенных страниц в 1.0.5 нет. Если проекту необходим такой вход, адаптер может изолировать применение внутреннего `llmw2.search.NoteSearch` с точной фиксацией версии и проверкой границ корпуса. При появлении публичного аналога заменяется только эта часть адаптера. Его отсутствие не требует форка CROW или нового формата знаний.

Исправления 1.0.2 удаляют YAML-метаданные из создаваемого тела заметки при `llm.note_steps` и уточняют язык ответа небольшой генерирующей модели. Исходник и его хеш не меняются; ранее импортированные статьи автоматически не переписываются. Русский язык пока отсутствует во встроенном детекторе этой подсказки. Эти исправления учитываются при выборе штатного импорта и ответов CROW; качество тематических статей и работу на языке проекта проверяют на своих примерах. [Изменения 1.0.2](https://github.com/crow-hq/llm-wiki-v2/releases/tag/v1.0.2) · [Детектор языка](https://github.com/crow-hq/llm-wiki-v2/blob/v1.0.5/src/llmw2/agents/lexical.py#L25-L51)

## Подключение к другому проекту

1. Выберите каталог и дайте агенту штатные средства чтения и редактирования. Для нового тестового корпуса достаточно создать пустую вики в формате OKF. Для существующего корпуса сначала проверьте на копии нескольких статей, распознаёт ли CROW метаданные, пути и ссылки.
2. Подключите поиск к тому же каталогу. CROW 1.0.5 непосредственно обнаруживает новый файл Note в тематической папке и видит изменение его текста при следующем чтении вне пакетного импорта. Повторно импортировать страницу ради поиска не требуется. При прямой правке сохраняйте ID, источники и незнакомые поля. При создании или переносе обновляйте индексы затронутых папок, ссылки и запись о правке в корневом `log.md`. Штатная проверка `Wiki.check()` обнаруживает пропущенную строку в индексе. Сам журнал от файловой правки не пополняется.
3. Следуйте принятому в проекте порядку сохранения. При управляемом исполнении агент оставляет законченные правки в рабочей копии, а коммит делает хост после проверки. При обычной работе с Git проект определяет, кто фиксирует результат. Хост включает только изменения завершённой операции. При пустой правке коммита нет. Согласуйте прямую запись с импортёром, если оба работают с общими файлами. Если у проекта есть собственный реестр или отдельный поисковый индекс, после коммита сверьте его с конкретной ревизией Git (SHA), включая новые, переименованные и удалённые страницы. Для самого CROW такая регистрация не нужна.
4. На одном примере проверьте, что новый вывод по двум темам меняет обе статьи и находится другим агентом, а повтор известного факта оставляет файлы без изменений. Проверьте прямую правку с последующим импортом близкого документа. Резервная копия должна содержать написанные агентом статьи. `rebuild` собирает вики заново из исходников и может потерять авторский текст, которого там нет.
5. При обновлении CROW повторите проверки подключённых операций. Для собственного адаптера отдельно проверьте версии API и ограничение входного корпуса. Если используются MCP, импорт или модельные ответы, проверьте их первый запуск, обработку исходников и качество на языке проекта. Подключение новой функции CROW учитывается отдельно от обновления зависимости.
