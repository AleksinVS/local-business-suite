# Блок: упрощение UX склада и общее автодополнение

- Идентификатор: `warehouse-ux-simplification`
- Статус: ready
- Риск: высокий — схема складских данных, права, конкурентные остатки и общий UI
- Владелец решений: пользователь, уточнения от 2026-09-02

## Цель

Реализовать простой складской UX без отдельного справочника серий: табличные
документы в правой панели, зависимое автодополнение, перемещение из списка
остатков, масштабируемые списки и понятные отчёты. Общий autocomplete должен
стать портальным компонентом, а не складской копией существующего кода заявок.

## Обязательные решения

- отдельного диалога подтверждения складского документа нет;
- строки документа — таблица;
- пользовательский термин `серия`, свободный ввод с подсказками;
- финальная схема не содержит отдельной таблицы серий;
- перемещение запускается из списка остатков и атомарно создаёт проведённый
  документ;
- создание и редактирование черновика — в правой панели;
- автодополнение применяется во всех значимых полях портала по проверяемой
  матрице;
- scope, FEFO, неотрицательный остаток, immutable ledger и XLSX сохраняются.

## Границы записи

Разрешённый общий scope задаётся task packets. Ни один исполнитель не меняет
чужой домен, contracts или общий shell за пределами своего пакета. Перед началом
каждого пакета исполнитель повторно читает `git status --short` и актуальную
версию файлов: репозиторий изменяется параллельно.

## Порядок

1. Пакеты 01 и 02 создают общую UI-основу.
2. Пакет 03 выполняет expand/migrate/contract серии.
3. Пакеты 04 и 05 выполняются параллельно после 01–03.
4. Пакет 06 может начинаться после контракта серии и общего autocomplete.
5. Пакеты 07a/07b используют только стабилизированный общий компонент.
6. Пакет 08 независимо проверяет миграцию, роли, UX и документацию.

## Обязательные артефакты исполнения

- `EXECUTOR_REPORT.<task-id>.md` для каждого выполненного пакета;
- `TASK_ACCEPTANCE.<task-id>.md` после проверки результата;
- матрица значимых полей в `docs/guides/PORTAL_AUTOCOMPLETE_FIELD_MATRIX.md`;
- миграционный отчёт серии без пользовательских данных в `.local/`;
- постоянные unit/integration/e2e тесты;
- `RETROSPECTIVE.md` и перенос блока в архив после приёмки владельцем.

## Запреты

- не добавлять сторонний тяжёлый UI-фреймворк без нового ADR;
- не делать общий endpoint, принимающий произвольную Django-модель;
- не переносить права в JavaScript;
- не сохранять частично выполненное массовое перемещение;
- не удалять `StockLot` до контрольной сверки новых полей;
- не расширять перемещение на другое подразделение;
- не добавлять подтверждающий modal перед сохранением или проведением.
