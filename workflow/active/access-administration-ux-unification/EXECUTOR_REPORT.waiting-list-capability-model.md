# Отчёт исполнения: модель прав листа ожидания

Реализована явная ролевая модель просмотра, создания, редактирования и переходов листа ожидания.

Основные изменения:

- области листа ожидания отделены от областей заявок;
- редактирование и переходы оцениваются как связанные гранты одной роли;
- глобальный граф статусов обязателен, включая суперпользователя;
- HTTP, правая панель, AI page context, AI service и source adapter используют ограниченную выборку;
- create/update/transition перечитывают активного пользователя и проверяют право внутри транзакции;
- старый runtime-контракт читается совместимо, но `manage_departments` больше не выдаёт права листа ожидания;
- новый контракт не публикует устаревший `view_waiting_list` и использует только `waiting_list_view_scope`;
- форма и Python/JSON Schema используют общий `values_source` и связанные инварианты.

Цикл исполнения: Luna-исполнитель → целевые тесты → Luna-критик → исправление → Luna-тестировщик → Sol security review → проверка основным агентом.

Проверки до миграции runtime:

- целевая матрица: 108 passed, 6 subtests;
- расширенная регрессия: 382 passed, 4 deselected, 46 subtests;
- JSON Schema/default: valid;
- `validate_architecture_contracts`: valid, runtime drift ожидаем до штатного применения.

Runtime применён через Settings Center preview/CAS/audit: `SettingsChange id=1`, статус `applied`, хеш `4634eded7d93…`. Существующие пять ролей и их несвязанные локальные отличия сохранены.
