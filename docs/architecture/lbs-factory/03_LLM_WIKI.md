# LLM-Wiki LBS Factory v3.4 — целевая модель с CROW/OKF

**Статус:** Accepted — согласованная редакция ADR-0051 от 13 ноября 2026 года. Документ задаёт целевое поведение. Приёмка CROW-интеграции ещё предстоит.

**Главные источники:** [ADR-0051](../../adr/ADR-0051-crow-pluggable-okf-knowledge-provider.md), [11_CROW_OKF_INTEGRATION.md](11_CROW_OKF_INTEGRATION.md), [12_CROW_IMPLEMENTATION_PLAN.md](12_CROW_IMPLEMENTATION_PLAN.md).  
**Открыто:** [политика ПДн в Wiki, CROW raw и Git](../../planning/active/knowledge-personal-data-git-policy-debt.md). Этот документ не устанавливает обязательное маскирование всех ПДн и не разрешает безусловную запись реальных ПДн в Git.

[Руководство для других проектов](../agent-wiki-architecture.md) содержит правила для навыка автора, карту инструментов CROW и порядок подключения к существующей вики.

## 1. Кто пишет в вики

Основной агент ведёт тематические статьи в общем корпусе OKF v0.2. После расследования он читает доступные страницы и документы целиком, дополняет или исправляет существующие объяснения, при необходимости создаёт новые и связывает их. Агент может обратиться к любой разрешённой статье, даже если её не предложил поиск. Материал одной задачи может уточнить несколько статей. Повторное наблюдение без нового вывода остаётся в задаче. В статье сохраняются вывод, условия применимости и проверяемое основание.

Для корпуса с CROW основной поиск, подбор темы для предлагаемой правки, обработка исходников, работа с противоречиями и реорганизация возложены на CROW с тонкими адаптерами LBS. В редакторском сценарии поиск и классификация доступны отдельно от записи. Агент сам меняет нужные файлы. Для необработанного документа доступен штатный импорт CROW. Обе операции используют один Git/OKF-корпус и принятый порядок доступа и записи в его раздел.

**Пример.** Из расследования выяснилось, какие строки таблицы допустимо передавать внешней модели и при каких правах можно открыть исходный лист. Агент читает «Обработка таблиц» и «Доступ к источникам», уточняет нужные разделы и добавляет ссылки на проверенный пример. При повторении проверки статьи могут остаться прежними. Если вместо результата расследования поступил новый регламент, CROW получает его разрешённую версию как исходный документ.

## 2. Сохранение текущих компонентов и роль FTS

Сохраняются `MemorySourceObject`, `MemorySearchDocument`, `SourceObjectEnvelope`, существующие Source Adapters, `memory.remember/search`, аудит, доменные права и legacy корпуса. Для CROW нужен локальный адаптер и регистрация как импортированных, так и созданных агентом Note в существующих проекциях LBS. Используются файловые инструменты и Git с поддержкой OKF. Не заменять `MemorySourceObject` на CROW `raw`.

**Для корпуса `provider=crow` основной поиск знаний выполняет CROW.** В v1.0.1 есть поиск `Wiki.search` без генерации ответа и отбор `Steps.select` при подготовке ответа. Выбор входа зависит от способа безопасно подать разрешённый набор страниц. Не строить второй конкурирующий пользовательский поиск по тем же Note. PostgreSQL FTS и существующие DB-проекции остаются для `source_data`, других не-CROW корпусов, регистрации, селекторов и аудита. После выключения CROW LBS обязан читать сами канонические Markdown-страницы, но не обязан обеспечивать прежнее качество classifier/CSV/history retrieval.

В LBS не было ранее внедрённой корпоративной Wiki. Имеются только материалы пробных прогонов. Новый корпус создаётся сразу в OKF, тестовые данные можно пересоздать. Перенос старых статей и отдельный мигратор для них не требуются. [Исходный отчёт P0](13_P0_BASELINE.md) остаётся описанием прежнего состояния кода. Этот вывод касается только Wiki; данные, права и настройки продуктивных бизнес-систем относятся к отдельной задаче. Записи с `lifecycle: pending` остаются закрытыми.

## 3. Операции, доступные агенту

| Намерение | Путь выполнения |
|---|---|
| Найти и дочитать | `knowledge.search/get`, переходы по ссылкам, чтение разрешённого Markdown в рабочем пространстве. CROW поддерживает поиск BM25, необязательные embeddings и подбор для ответа. Возврат результатов ограничивается правами на пространство и статью. |
| Подобрать тему, страницу или характер изменения | Необязательная консультация у адаптера CROW. Поиск даёт кандидатов, типизированный вопрос сопоставляет предложенное уточнение с ними. Пустой или неоднозначный ответ возвращает выбор агенту. Никаких файловых изменений. |
| Написать знание, которое уже осмыслено | Обычные операции создания и редактирования OKF Markdown в пределах полномочий. Основной агент сам формулирует окончательную редакцию. В сетевом профиле хост ограничивает доступную рабочую область. Для этого не требуется новый API публикации или новая служба. |
| Передать новый первоисточник | Существующий вход для исходного текста или документа, в профиле CROW — `Wiki.ingest` или `sync` разрешённого представления. Сохраняется совместимость прежних вызовов `save_working`/адаптеров в их исходном назначении. Авторские страницы не передаются сюда автоматически. |
| Получить расширенный контекст | `knowledge.prepare_context` подбирает доступные тексты, строки таблиц, архивные версии и указания на расхождения. Основной агент может дочитать основание и готовит ответ с проверяемыми ссылками. |
| Обслужить структуру или состояние | CROW предлагает и выполняет допустимые перемещения и изменения областей. `knowledge.flag_confirmation/list_confirmation/confirm` управляют подтверждением. Целевой `knowledge.reconcile` сверяет проекции выбранного корпуса с опубликованной Git-ревизией. |

Это логические возможности существующих интерфейсов. Интеграция не вводит обязательный вызов классификатора перед обычной редактурой. Краткий поиск и подготовка расширенного контекста остаются разными операциями. Варианты получения контекста из полностью разрешённого раздела и через существующие Source Adapters LBS описаны в [контракте интеграции](11_CROW_OKF_INTEGRATION.md). Выбор способа обслуживания корпуса не даёт агенту права читать сырые или исторические данные.

## 4. Единый канон OKF и отдельное служебное состояние

Пример первого запуска (bundles — **соседние**, не вложенные друг в друга):

~~~text
data/knowledge_repo/
  org/
    sources/                    # существующие LBS-корпуса
    crow/
      common/                   # CROW OKF bundle
        index.md / log.md / ...Note.md
        raw/                    # вне Git
        .archive/               # вне Git
        .llmw2/sync/            # вне Git
      accounting/               # второй самостоятельный bundle
      accounting-restricted/    # отдельная write-partition при необходимости
~~~

- **Git:** утверждённые для данного места хранения OKF Notes, индексы, журнал, версии и стабильные `knowledge_id`.
- **CROW raw/.archive/.llmw2/sync:** функционально необходимые вспомогательные источники, прежние редакции и курсоры; **не в Git**. Их защищать и восстанавливать **отдельно**.
- **PostgreSQL:** LBS Access, соответствие `space_id → bundle_id[]`, редкие Note-level ограничения, `MemoryKnowledgeItem/MemorySearchDocument` и аудит. Проекции можно пересоздать.
- **Домен/внешняя система:** исходные бизнес-объекты и оригиналы. CROW raw — подготовленная версия, а не обязательно побайтная копия оригинала.

`.gitignore` не останавливает рекурсивный обход файлов. Legacy `_walk_knowledge_files`, `memory_reconcile`, общий `org/index.md`/`org/log.md` и graph materializer **не должны читать/переиндексировать весь CROW-managed namespace**, включая `raw` и `.archive`. Одинаковая регистрация охватывает новые импортированные и авторские Note. Проектор обновляет метаданные без обратной перезаписи авторского текста. `write_knowledge_item_file` сейчас пересобирает Frontmatter: нельзя им без нормализации перезаписывать CROW-страницы и терять `sources/id/generated` или неизвестные ключи.

## 5. Поля OKF и состояние знания в LBS

Пример целевого Frontmatter Note (не текущая реализация writer):

~~~yaml
---
type: Note
id: "crow-note-a81fae39"
knowledge_id: "knw-maintenance-intake"
title: "Приём заявок"
description: "Фактические каналы регистрации заявок"
lifecycle: current
confirmation_state: working
sensitivity: internal
sources:
  - id: s1
    resource: /raw/20261021-intake.md
    title: "Интервью технической службы"
---
~~~

**Не смешивать:**

- Поле OKF `status` необязательно. Если автор его опустил, LBS трактует статью как `stable`; у обычной текущей статьи внутренняя запись `MemoryKnowledgeItem` получает `active`. Это значение по умолчанию не нужно дописывать в Markdown. Входящие `draft` и `deprecated` сохраняются и учитываются в выдаче как черновик и устаревшая редакция соответственно. CROW 1.0.1 сам по `status` заметки не отфильтровывает; правила видимости и использования применяет LBS.
- `confirmation_state: working|needs_confirmation|confirmed` — отдельная достоверность. `confirmed` требует подтверждения именно данной редакции; после смысловой машинной правки прежнее подтверждение не переносится автоматически.
- `lifecycle: current|pending` — отдельный LBS-контур; legacy `pending` не становится видимым из-за `status: stable`.

При записи не удалять unknown Frontmatter, `sources`, native ID, `knowledge_id` и валидные `verified`. Никаких списков пользователей/ролевых grants в YAML. Внутренние `index.md`/`log.md` должны соответствовать OKF v0.2; `log.md` имеет ISO-даты. Текущие схемы LBS не всегда поддерживают `type`/`status`/формат log — **исправить reader/writer/валидацию/фикстуры до первого реального корпуса**.

## 6. Два сценария записи в один корпус

**Прямая редактура.** Агент работает разрешённым файловым инструментом в своей области. Перед значимой правкой он читает актуальную версию, проверяет, что именно изменилось, и редактирует тематические страницы. В том же порядке работы поддерживаются ссылки, записи навигации и журнал операций. Журнал и транскрипт не служат шаблоном статьи. Перед завершением сверяются фактический diff, основания и актуальность ранее прочитанной версии. При конкурирующей правке агент перечитывает затронутый файл. Отдельный шаг повторной генерации или пакетная транзакция над статьями не требуются.

**Импорт.** LBS передаёт CROW подготовленный исходник с идентичностью и версией в разрешённый раздел. CROW может выполнить `route/match/consolidate/merge/relate`. Импорт и реструктуризация учитывают авторские разделы и основания наравне с остальным действующим знанием. До окончания записи проверяется итоговый diff. Если импорт затронул авторский текст неприемлемым образом, сохраняют последнюю согласованную версию, разбирают затронутые источники и корректируют результат. Каталог вики не используется как источник её же ingest/sync.

**Фиксация.** В управляемом LBS хост завершает успешную правку обычным Git-коммитом только проверенных файлов этой операции, включая относящиеся к ней ссылки и навигацию. Соседние незавершённые правки и уже подготовленные чужие файлы остаются у их авторов. Пустое изменение не создаёт коммит. Внешний агент следует Git-порядку своего проекта; LBS обрабатывает его опубликованную ревизию после получения изменений. Окончание хода чата или закрытие клиента само по себе ничего не фиксирует.

Во время записи участники видят предыдущую завершённую версию либо ждут. После фиксации LBS сверяет изменившийся корпус с конкретным коммитом, обновляет регистрацию, поиск и кэши. Сбой индексации отражается как `index_pending`. Текущий `memory_reconcile` требует доработки для обнаружения новых страниц и переносов. [Порядок сверки](11_CROW_OKF_INTEGRATION.md#46-что-индексируется).

**Таблицы.** В CROW `Wiki.ingest_file(xlsx)` разбивает книгу до `Steps.extract`. Когда права различаются по строкам, LBS сначала формирует разрешённый текст листа и стабильный `Origin.id=file_id#sheet`. Переданный CROW текст, включая его raw-копию, уже соответствует правам и назначению.

## 7. Доступ до поиска, raw и ответа

Правило: **проверенный actor AND доступ к space AND зарегистрированная читаемая Note AND Note restrictions AND sensitivity/destination AND аудитория**. Note-level исключения **только сужают** доступ пространства. Текущий OR-`scope_tokens_match` сам по себе не обеспечивает это AND-наследование.

**Быстрый `select`:** до вызова `Steps.select` и любых classifier-операций LBS на основе кэшированного полного дерева доверенного процесса вычисляет batch ACL, затем создаёт request-local *копии Folder и Note* с разрешёнными `id/title/description/rel` и необходимыми допустимыми фрагментами текста. В v1.0.1 тело может участвовать в BM25 и переранжировании. Если передаётся функция поиска, её индекс и кандидаты также ограничены той же областью. Закрытые фрагменты, основания, ссылки и папки исключаются до любого модельного вызова. В CROW `check_select` сверяет идентичности Note внутри **переданного scoped root**, поэтому разрешено выбирать Note-копии, если root и результат используют одни объекты. Классификатор не должен видеть запрещённые заголовки или пути.

**Полный `prepare_context`.** В полностью доступном разделе возможна штатная подготовка CROW. При смешанных правах существующие Source Adapters и средства чтения LBS отдают разрешённые страницы, цитаты, строки и версии. При необходимости адаптер может реализовать `ScopedReadStore` для конкретной версии CROW. Во всех вариантах LBS проверяет доступ к каждому исходнику и архивной версии, включая допустимость передачи данных адресату. Чтение raw/архива не становится разрешённым только из-за права видеть Note. Пропускать запрещённое с явным признаком **неполного контекста**, затем повторно проверять citations, ссылки `See also`, права и аудиторию ответа.

**Кэш:** штатный `WikiStore.load()` читает YAML и body в память. Загружать один базовый снимок на версию физического bundle, а не на каждый вопрос; сам снимок нельзя передавать модели. Создавать лёгкий scoped view на запрос, invalidate при изменении прав/версии. Для нескольких workers проверить версию через LBS; общий RAM-кэш между процессами **не предполагается**. `select_and_hydrate`, per-user persistent views и Source API — поздние оптимизации при измеренной пользе.

## 8. Подтверждения и статус сведений

Новый вывод из интервью становится рабочей тематической статьёй или уточнением существующей с указанием источника и сразу доступен разрешённым участникам. `needs_confirmation` добавляет запись в неблокирующий реестр (противоречие, возможная устарелость, требование регламента), не задерживая сбор знаний. Реестр — перестраиваемая проекция OKF; сбой реестра не мешает writer.

`_conflicting` CROW формирует возможную подсказку при подготовке ответа, **не** автоматически достоверный спор и не обязательный human review. Privacy-block не переводить в `needs_confirmation`. Официальное подтверждение и изменение прав — отдельные полномочия. Смысловая правка подтверждённой Note требует новой оценки статуса.

**Как закрыть расхождение.** CROW подбирает спорящие фрагменты. Если это новая версия одного исходного документа, применимы штатные правила ревизий. Для двух разных источников основной агент проверяет даты действия, контекст и авторитет каждого. Например, две разные нормы могут одновременно действовать в разных подразделениях. Тогда агент добавляет область применимости в обе статьи. Если подтверждён факт замены нормы, исправляет действующее правило и сохраняет ссылку на прежнее. Если источников недостаточно, оставляет обе версии с пометкой о том, что требует проверки. Одна оценка модели или дата загрузки не снимает противоречие.

## 9. Приватность и политика ПДн

Content Privacy Pipeline [10](10_CONTENT_PRIVACY_PIPELINE.md) — единая граница для Source Adapters, raw, индексов, Wiki и LLM; CROW **не** запускает вторую подсистему обезличивания. Текущие три профиля применяются **согласно выбранной политике назначения**; универсальное PII-сканирование и принудительное маскирование не утверждены. Для закрытого допустимого on-prem сценария CROW raw может включать реальные ПДн; для Git и внешней модели нужны **отдельные явные правила**.

До реальных чувствительных источников решить [долг по ПДн](../../planning/active/knowledge-personal-data-git-policy-debt.md): что допустимо в Git, raw, archive, FTS, бэкапах, какую LLM можно использовать и как удалять/пересоздавать производные знания. Пока — синтетический пилот или отдельно согласованные безопасные источники. Не раскрывать секреты в commit message, CROW index/log, trace или prompt. Проверять фактический результат и нативного импорта, и прямого редактирования, включая названия, индексы и ссылки.

## 10. Восстановление и отключение модуля

CROW пишет несколько файлов без общей транзакции. Для прямых правок и операций CROW нужен общий порядок эксклюзивной записи в раздел, барьер чтения во время записи, минимальный журнал/маркер незавершённой операции, предкоммитная валидация и тест прерывания между raw и Note, между Git и индексом. Для L0 не нужен распределённый координатор.

**Backup/restore:** комплект **Git + CROW raw + .archive + .llmw2/sync + конфигурация space/Access** и восстановимые БД-проекции; один Git clone не обеспечивает полную историю исходников. При аварии запрещено смешивать новый Note body со старым raw.

После выключения CROW канонические OKF-файлы остаются доступны для разрешённого чтения и прямой редактуры через LBS; полноценный classifier-select, строки таблиц и архивные подсказки без другого провайдера не обещаются. При смене провайдера завершают текущую операцию, сверяют OKF и основания, проверяют совместимость поиска и ссылок.

## 11. Что не вводить заранее

Не внедрять полноценный второй интеллектуальный поиск по тем же CROW Notes, обязательный OpenFGA, публичный Source API внутри CROW, замену `MemorySourceObject` на raw, S3, event bus, собственный CROW fork, полную mixed-ACL обработку внутри одного bundle, per-user дерево и обязательный DLP/NER. Это возможные варианты эволюции с тестами, а не условия первого запуска.

**Лицензия CROW — AGPL-3.0-or-later:** до коммерческого включения, распространения или предоставления модифицированной сетевой службы провести лицензионную проверку и выбрать допустимый способ использования/лицензию.

## 12. Проверочная матрица (синтетические данные до политики ПДн)

| ID | Проверка | Результат |
|---|---|---|
| W-01 | Обычная статья без `status`, импорт черновика и устаревшей статьи | Обычная статья сохраняется и проецируется как `stable`/`active`. Входящие `draft`/`deprecated`, неизвестные поля, ID и источники сохраняются. Видимость проверена в LBS, index/log корректны |
| W-02 | Серия интервью | Рабочая Note без human-review, статус/источник, реестр не блокирует |
| W-03 | Подтверждённая Note изменена агентом или CROW | Старое confirmation не переносится |
| W-04 | 2 пространства + Note-level deny | Запрещённые title/description/folder не попадают в select/classifier |
| W-05 | Ingest несовместимых ACL | Нет cross-ACL merge/relate/plan, безопасная write-partition или отказ |
| W-06 | search против prepare_context | Быстрый select не выдаёт историю/CSV/conflict, полный контекст выдаёт только разрешённые |
| W-07 | Note доступна, raw запрещён | Note видна, raw не выдаётся; ответ помечен как неполный |
| W-08 | Egress закрыт | Нет облачного prompt с запрещённым текстом/заголовком |
| W-09 | Сбой между raw и Note | Read barrier/recovery не выдаёт полусостояние |
| W-10 | Сбой после commit до project | Нет устаревшего «current» индекса; reconcile возвращает состояние |
| W-11 | raw и archive вне Git и legacy обходов | Нет в `git ls-files`, FTS/org index и общем логе |
| W-12 | Повторный Origin, новая transform version | Идемпотентность и корректный update |
| W-13 | Отключённый CROW | Базовый read OKF без runtime; no new native writes |
| W-14 | Backup/restore | Git/raw/archive/sync/Access и ссылки восстановлены |
| W-15 | Обновление upstream | Контрактные тесты фактически подключённых шагов и адаптеров, проверка AGPL |
| W-16 | XLSX с row ACL | До CROW разделение/очистка, `_with_rows` не видит закрытые строки |
| W-17 | Агент за одну задачу уточняет две известные страницы, затем повторяет наблюдение | Сохранены обе редакции и их основания, повтор не создаёт статью. По журналу вызовов нет повторного ingest авторского текста |
| W-18 | Классификация правки и обход соседней статьи | Подсказка не меняет файлы и Git. Агент читает разрешённую статью вне первоначальной выдачи |
| W-19 | Два источника расходятся | Различены подсказка CROW и решение с основаниями. Неподтверждённая версия остаётся видимой как спорная |
| W-20 | Прямая новая статья и последующий перенос CROW | Статья находится по содержанию с верным ID; навигация и ссылки после переноса ведут к ней; авторский текст сохранён |
