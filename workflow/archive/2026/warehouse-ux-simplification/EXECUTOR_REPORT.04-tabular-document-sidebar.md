# Исполнительский отчёт 04 — табличный документ в правой панели

## Результат

Реализован серверный редактор складского документа с правой панелью и прямым
полностраничным запасным маршрутом. Документ создаётся и изменяется одной
табличной формой; строки можно добавлять и удалять без отдельного блока формы.
Тип операции управляет видимостью адресных полей и причины. Номер строки
передаётся только как скрытое техническое поле и заново назначается сервером.

Проведение и сохранение используют HTMX: повторная отправка формы отбрасывается
клиентским `hx-sync`, а создание защищено ключом идемпотентности. Ошибка
проведения или проверки возвращает 422, сохраняет все введённые строки и
показывает ошибку рядом с формой/строкой. Проведённый документ не открывается
на редактирование.

## Изменённые файлы

- `apps/warehouse/forms.py` — operation-aware line form, серверная нумерация и
  проверка непустого набора строк;
- `apps/warehouse/views.py` и `apps/warehouse/urls.py` — panel/full-page
  create/edit/detail маршруты, scope revalidation, idempotency и 422;
- `apps/warehouse/right_panel.py`, `apps/warehouse/apps.py` — безопасный
  серверный провайдер дескрипторов правой панели;
- `templates/warehouse/partials/` и существующие шаблоны документов — таблица,
  HTMX-форма, доступные кнопки и сохранение введённых значений;
- `static/src/warehouse/document_editor.js` — добавление/удаление строк,
  динамические колонки, keyboard focus;
- `static/src/css/warehouse_document.css` — прокрутка широкой таблицы и narrow
  viewport;
- `apps/warehouse/tests/test_document_sidebar.py` — focused HTTP/formset/security
  проверки.

После независимого ревью дополнительно исправлены: sequence исключён из
связанной формы и назначается только сервером, восстановлены поля причин
неполных данных и отклонения FEFO, добавлены складские autocomplete providers и
их scoped-маршруты, уникальные id listbox, корректное клонирование удалённых
строк, структурированное сопоставление ошибки с номером строки, три события
обновления после успеха и восстановление при гонке уникального idempotency key.
Финальная корректировка добавила перенос индексов во всех
`data-autocomplete-context`, провайдеры серий только по опубликованным остаткам
с фильтром позиции/подразделения, operation-aware адреса с положительным
остатком для расхода, автозаполнение серии срока/адреса/источника, структурные
атрибуты `line_sequence`/`line_index`/`field` для ошибок проведения и безопасный
повтор проведения опубликованного документа (изменённый повтор получает 409).

## Проверки

- `python -m compileall -q apps/warehouse/...` — пройдено;
- `node --check static/src/warehouse/document_editor.js` — пройдено;
- `manage.py test apps.warehouse.tests.test_document_sidebar --verbosity 1` — 6
  тестов пройдено;
- `git diff --check` — пройдено;
- `manage.py check` — пройдено с существующим предупреждением о недоступном
  состоянии миграции центра настроек.

Полный Django/pytest прогон в текущем общем рабочем дереве не завершён:
параллельный агент удерживает общий `.local/test-default.sqlite3`, а отдельный
SQLite прогон останавливается на создании тестовой базы. Повторить focused
тесты после освобождения базы и выполнить UI-профиль должен основной агент.

## Интеграционные ограничения

Шаблоны используют provider-коды `warehouse.item`, `warehouse.series`,
`warehouse.source`, `warehouse.location` и `warehouse.department` через общий
`AutocompleteView`, смонтированный доменными URL склада. Провайдеры регистрируются
при загрузке приложения; сервер дополнительно не принимает неразрешённые
значения благодаря ModelChoice/queryset и scope-проверкам. Общий `/ui`-алиас и
остальные бизнес-формы остаются интеграционной задачей пакета 07a.

Изменения не коммитились и не отправлялись в удалённый репозиторий.
