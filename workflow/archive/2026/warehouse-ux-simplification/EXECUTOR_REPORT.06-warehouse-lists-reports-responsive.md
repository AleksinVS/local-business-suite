  поиск, подразделение, склад, адрес, состояние срока годности и период/дата.
- Добавлен изолированный адаптер `apps/warehouse/report_views.py`. Он применяет
  одинаковый отбор к HTML, CSV и XLSX, отдаёт HTML постранично (100 строк) и
  предоставляет helper для постраничных списков.
- Наборы данных обогащены точностью единицы и состоянием адреса.
- Экспорт теперь использует русские пользовательские заголовки, исключает
  технические `*_id`, форматирует количество согласно `quantity_precision` и
  сохраняет защиту от формул в CSV/XLSX.
- Отчётный шаблон получил видимые фильтры, счётчик результатов, состояние
  отсутствия данных, экспорт и постраничную навигацию.
- Добавлен CSS для фильтров и безопасного отображения таблицы на ширине 390 px.
- Добавлены сфокусированные unit-тесты точности количества, фильтрации сроков и
  русских экспортных заголовков.
- Порог истечения берётся единым проверенным снимком `warehouse.settings` на
  запрос; добавлены состояния адреса `Доступно`, `Карантин`, `Адрес не назначен`.
- Наличие группируется с сохранением состояния адреса, поэтому карантин не
  смешивается с доступным остатком.
- Выборка отчётов ограничивается датой на уровне queryset и больше не делает
  `list()` всего журнала до агрегации; постраничный HTML ограничен 100 строками,
  а полный материализованный набор создаётся только при явном экспорте.
- Списки складов, адресов, профилей отчётов и каталогов получили поиск,
  стабильную сортировку, постраничную выдачу, счётчик найденных записей и
  отдельное состояние пустого результата; фильтр сохраняется в ссылках
  редактирования и пагинации.
- Ошибки фильтров отчёта теперь возвращают форму с HTTP 422 и сохраняют
  введённые значения; в HTML показывается выбранный `WarehouseReportProfile`.
- Добавлено покрытие реальных URL отчётов профилем подразделения и
  ограниченной выдачей каталога (60 записей).
- Пустой `GET` теперь является валидным фильтром: все три рабочих URL
  отчётов открываются с кодом 200. Для расхода скрыты неприменимые измерения
  склада (склад, адрес и срок годности).
- Для сроков годности отображаются отдельные полосы из `warehouse.settings`
  (например, 0–30, 31–90 и 91–180 дней), а не только максимальный порог.
- В наборы данных добавлен явный защитный предел 10 000 групп. При превышении
  сервер возвращает понятный HTTP 413 с пределом и предложением уточнить
  фильтры; CSV/XLSX не обрезаются и полностью выгружаются в пределах этого
  предела.

## Ограничения интеграции

Роутинг и подключение CSS намеренно не менялись: `views.py`, `urls.py`, `base.html`
исключены из write scope и одновременно редактируются другими агентами. Точный
минимальный патч для основного агента:

```python
# apps/warehouse/views.py — в каждом из трёх существующих handlers
return report_view(
    request,
    report_kind="expense",  # rack-card / availability в соответствующем handler
    actor=request.user,
    department_ids=_report_scope(request),
)
```

```python
# templates/base.html (или отдельный report-only include)
<link rel="stylesheet" href="{% static 'src/css/warehouse-reports.css' %}">
```

Проверено, что `WarehouseReportProfile` сохраняется в контексте HTML и в
метаданных CSV/XLSX. Для списков пагинация применяется после scoped selector
и поиска; в коде складского раздела больше нет немых ограничений `[:200]`.

Остаточный риск вне данного write scope: в режиме перемещения отдельная
выборка остатков пока требует независимой проверки ограничения размера
списка и серверной пагинации; relocation-файлы в этой корректировке не
изменялись.
