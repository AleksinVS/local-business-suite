# Отчёт исполнения: contract, Board, role impact и memory groups

Дата: 2026-08-12.

## Выполнено

- `00c`: рабочие контракты получили staged-протокол
  `PENDING → atomic replace → APPLIED`, общий Linux/Windows lock, обязательный
  CAS, снимки восстановления, `INCONSISTENT`, dry-run/apply reconciliation и
  авторизованный rollback.
- Изменение определения роли и членства пользователей использует один lock;
  actor, состав участников и impact повторно проверяются перед записью.
- AI confirmation атомарно занимает одноразовый `PendingAction`, выполняет
  инструмент вне транзакции и фиксирует терминальный статус с аудитом одной
  транзакцией. Неопределённый результат имеет отдельный операторский сценарий
  `reconcile_ai_action`: он пишет наблюдение и идентификатор оператора, но не
  закрывает статус без fencing-протокола.
- `00d`: `Board.allowed_groups` и технические группы памяти изменяются только
  подписанными доменными preview/apply-сервисами с обязательной причиной и
  предметным аудитом. Django Admin остаётся резервным клиентом Board/role
  сервисов, но прямые поля закрыты.
- Клонирование доски переносит структуру без скрытого ACL. Demo bootstrap
  назначений пользователей и досок аудируется и не перезаписывает сторонние
  назначения. Заранее созданные миграциями канонические доски `main` и
  `backlog` допускают единственную bootstrap-инициализацию только при пустом ACL
  и отсутствии истории; произвольная существующая доска отклоняется.
- `03`: массовый редактор заменён каталогом и точечным редактором одной роли.
  Impact учитывает уникальных участников, совмещённые роли и связанные пары
  `transition_scope`/`transition_targets`.
- UX дополнительно упрощён: ссылки зависят от реальных полномочий, длинные
  заголовки переносятся, таблицы доступны клавиатурой, предпросмотр получает
  фокус, а действия имеют мобильную область нажатия.

## Безопасность

- стандартный User Admin не меняет профиль, пароль, роли, permissions, флаги,
  активность, подразделение, не создаёт и не удаляет пользователей;
- AD identity в Admin доступна только для чтения;
- профиль, lifecycle пользователя и AD-связь сериализуются общим lock доступа и
  записываются в одной транзакции с `SettingsChange`; логин, email и AD principal
  представлены только версионированными HMAC-отпечатками;
- AI user-update подписывает actor/target before+after, отклоняет устаревшее
  подтверждение и атомарно меняет активность и подразделение;
- общий writer `AgentActionLog` рекурсивно очищает identity-поля request/response;
- LDAP profile/identity sync использует общий lock и безопасный аудит; `manual`
  не перезаписывает ручную identity, `automatic` является явным режимом записи;
- Board impact подписывает состав активных пользователей, включая базовый
  customer-профиль пользователя без контрактной роли;
- неизвестные capabilities, технические/legacy Board-группы и устаревшие
  предпросмотры завершаются закрытым отказом.

## Сквозная проверка

`access_administration_e2e` через Django HTTP-клиент меняет `view_scope` роли,
проверяет два результата доступа к конкретной заявке, пользователя с совмещёнными
ролями, Board ACL, техническую группу памяти и три предметных журнала. Тестовые
объекты удаляются в `finally`.
