# Приёмка задачи 04 — табличный документ в правой панели

Статус: принято основным агентом после цикла Luna-исполнение → тесты → Luna-xhigh критика → Luna-исправление → финальная проверка.

## Принятый результат

- Создание и редактирование складского документа выполняются в общей правой панели.
- Строки вводятся в таблице; `sequence` не доверяется браузеру и назначается сервером.
- Нет отдельного подтверждения документа: пользователь сохраняет черновик либо сразу проводит его.
- Серия остаётся текстовым полем с автодополнением по проведённым положительным остаткам.
- Подсказки учитывают подразделение, вид операции, позицию, серию, источник и доступный адрес.
- Выбор серии заполняет срок, источник и видимый/скрытый адрес; FEFO и причины отклонения остаются редактируемыми.
- Ошибки доменных проверок содержат устойчивую идентификацию строки и возвращаются в нужную ячейку.
- Повтор создания и повтор проведения редактируемого документа идемпотентны только при неизменном содержимом запроса.
- После успеха публикуются события обновления документов и остатков.

## Проверки

- Luna-xhigh критика выявила ошибки нумерации, контекста подсказок, FEFO, адресов, привязки ошибок и повторных запросов; исполнитель их устранил.
- Исполнитель: `6` тестов `apps.warehouse.tests.test_document_sidebar` успешно, `compileall`, `node --check` и `git diff --check` успешно.
- Основной агент повторил `pytest apps/warehouse/tests/test_document_sidebar.py` на отдельной SQLite-базе: `6 passed`.
