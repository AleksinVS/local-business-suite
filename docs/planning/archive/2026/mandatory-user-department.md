# Обязательное подразделение пользователя

Статус: завершено 2026-08-05.

## Цель

Запретить пользователей без подразделения на уровне формы и базы, сохранив
безопасный переход существующих данных и работоспособность AD/служебных сценариев.

## Решение

- `User.department`: `PROTECT`, `null=False`, `blank=False`;
- старые `NULL` → дочернее карантинное подразделение;
- новые программные записи без подразделения → тот же карантин;
- UI не предлагает карантин как нормальный выбор и показывает предупреждение;
- новое решение зафиксировано ADR-0035.

## Проверки

- миграция вперёд/назад на чистой тестовой БД;
- перенос `NULL` без назначения корневого агрегатора;
- обязательность форм создания и изменения;
- fail-closed видимость заявок для карантинного пользователя;
- `make check`, затронутые тесты, `make contracts`, PostgreSQL migrate/e2e.

## Результат

Инвариант внедрён на уровне формы, модели и базы. SQLite и PostgreSQL перенесли
старые `NULL` в безопасный карантинный узел. На рабочем PostgreSQL после
миграции: 24 пользователя, `NULL` — 0, требуют ручного назначения — 17.

Целевые тесты и e2e прошли. Полный набор: 545 passed, 65 subtests passed,
2 ранее известных несвязанных падения в `apps/ai/tests/test_views.py` из-за
устаревших ожидаемых версий статических файлов ИИ-интерфейса.
